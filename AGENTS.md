# Errant Fox — карта проекта для ИИ-ассистентов (читать первым)

Общий файл для Claude (CLAUDE.md) и Gemini (GEMINI.md): оба импортируют этот файл. Правки вносить сюда.

Платформа видеоанализа спаррингов HEMA (в основном длинный меч; бывают копьё, одноручный меч, сабля, меч и баклер; тренировки и турниры).
Владелец говорит по-русски — отвечать по-русски.

## v1 — работает в проде

Прод = ветка `master` на GitHub `geometrik32/errant-fox` (репозиторий **публичный**).
Push в `master` → GitHub Actions (`.github/workflows/docker-publish.yml`) собирает образы в ghcr.io → TrueNAS SCALE тянет их через `docker-compose.yml`.

| Путь | Что это |
|---|---|
| `backend/` | Rust: Axum + Diesel + SQLite. Маршруты — `src/api/mod.rs`, схема БД — `src/db/schema.rs` |
| `frontend/` | Svelte 5 + TypeScript + Vite |
| `whisper-service/` | Python, авторазметка сходов по звуку (Faster-Whisper) |
| `docker-compose.yml` / `docker-compose.dev.yml` | прод / локальная сборка |
| `docs/` | документация: architecture, api, database, deploy, quickstart_local, requirements; `docs/history/` — устаревшее |
| `DESIGN.md` | дизайн-код интерфейса |
| `llms.txt` | краткое описание проекта для LLM |
| `execution/compress_adaptive_vfr.py` | адаптивное сжатие видео (сходы — 100 fps, паузы — 25 fps) |
| `scripts/check_users.py` | просмотр пользователей в SQLite |

Видео лежат в Seafile (`SEAFILE_URL`), не в репозитории.
Чего не хватает в v1: тегов на видео (тип оружия, турнир/тренировка — турнир сейчас определяется только по имени папки).

## v2 — 3D-реконструкция схода (начинаем с нуля)

Цель: монокулярное видео схода (~2 с) → 3D-сцена: пол, камера, анимированные скелеты двух бойцов (с кистями), клинок, достроенный от кистей.
Конвейер:
1. Положение камеры относительно облака точек зала (фотограмметрия) + прямоугольник арены на полу.
2. Детекция и трекинг двух бойцов (дообучаемая модель), отсечение зрителей.
3. 2D-скелет (свой: ноги, торс, руки, кисти, нос) с дообучением по ручным исправлениям.
4. 2D→3D: каждая точка лежит на луче камеры, допуск — конус; референс — GVHMR; дообучение по исправлениям.
5. Метрики техники: выпад, порядок «руки → ноги», дистанция, скорость, защита.

Прошлые попытки не дали даже стабильного п.1 — не копировать старые решения вслепую.
Ветки: `master` — только прод; `v2` — долгая ветка 3D-конвейера (код в `v2/`); `exp/<имя>` — короткие эксперименты.
Планирование v2 ведётся в файлах: `v2/planning/task_plan.md` (этапы, решения), `findings.md` (находки), `progress.md` (журнал). В начале сессии читать, после этапа обновлять.

## Правила

- Не коммитить и не пушить без явной просьбы. `master` = прод: push сразу выкатывается.
- Секреты только в `.env`. Никогда не вставлять токены в текст команд: разрешённая команда сохраняется в настройках ассистента целиком и так уже утекала в публичный git (07.11.2026 история вычищена, токены перевыпущены).
- На большой или размытой задаче сначала задать уточняющие вопросы с вариантами ответа, потом действовать.

## Как работать (принципы Karpathy, multica-ai/andrej-karpathy-skills)

1. Сначала думай: называй допущения; при неясности спрашивай; если трактовок несколько — покажи их, не выбирай молча.
2. Простота: минимум кода, ничего «на вырост».
3. Точечные правки: каждая изменённая строка следует из запроса; чужой код не «улучшать».
4. Работа от цели: у каждого шага есть проверка («шаг → verify: …»); крутиться, пока не проверено.
